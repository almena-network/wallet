# Almena Wallet — notes for contributors and agents

The user's app for Almena Network, a decentralised messaging platform based on DIDComm Messaging v2.0
(https://identity.foundation/didcomm-messaging/spec/v2.0/). It talks to an Almena mediator (`../mediator`).

This project is independent: it has its own tooling and shares nothing with `../mediator` except the protocol.

## Layout

- `src/` — React + TypeScript front end (Vite). Package manager: pnpm.
- `src-tauri/` — Tauri v2 Rust side (`wallet_lib`).
  - `identity/`: BIP-39 phrase → seed → SLIP-0010 `m/0'` → ed25519 `did:key`. The derivation is frozen and pinned by test vectors; changing it makes existing phrases open a different identity. The seed is held in memory while the wallet is open and never crosses to the front end.
  - `vault/`: the seed on the device between launches — a versioned record (Argon2id + XChaCha20-Poly1305, 10 PIN attempts) kept in the platform's secret store, or a private file on Android. Every PIN check goes through `attempt`. Changing the PIN rewraps the data key and leaves the seed as it was. Biometrics put a copy of the data key in a store the system holds behind its own presence check (`require-user-presence`): the protected keychain on iOS, the data protection keychain on a signed macOS build with a sensor (probed at startup, `presence.rs`); arming costs the PIN and is proven by reading the key back. Windows, Linux and Android do not offer it.
  - `messaging/`: the mediation with a DIDComm mediator and the relationships through it, on `almena-didcomm` (git dependency on `../mediator`'s repository, pinned to a tag). Every DID is a `did:peer:2` derived from the seed whose service routes through the mediator (`peer.rs`): the inbox (`m/1'`, keys the mediation, never shared), the contact card (`m/4'`, named by the wallet's OOB invitation) and one pairwise per counterparty (`m/3'/…`, from a hash of the counterparty's DID). DIDs other than the inbox are registered with a possession proof. A relationship opens with a Trust Ping from the accepter's pairwise to the card, answered from a new pairwise with `from_prior` signed by the card (`contacts.rs`). The mediator and the relationships are sealed under `m/2'` (`state.rs`); no secret key is stored. Requests to the mediator are authcrypted with `return_route: "all"`, and each operation re-sends the idempotent `mediate-request` first. Once open, a relationship carries text (Basic Message 2.0) and each side's name (User Profile 1.0, `displayName` only), always over the pairwise (`chat.rs`): the inviter sends its name after the `ping-response` with `send_back_yours`, and a changed name goes to every contact. A contact's alias is local and wins over their name. The inbox summary (name, unread, last message) lives in the state; each conversation's history is its own sealed file, named and bound (AAD) by a hash of our pairwise (`conversation.rs`), deduplicated by message `id`, so a retried message keeps its id. While the wallet is visible and open, `live.rs` holds a WebSocket to the mediator with Pickup live delivery on: each session starts with a sync (the backlog is not pushed), pushed `delivery`s go through the same `handle`/`apply` under the same `Gate` and are acknowledged on the socket, and changes reach the interface as the `messaging-changed` event; it pings when quiet, reconnects with backoff, and stops on sign-out. `push.rs` registers the device token (FCM on Android, APNs on iOS, via `tauri-plugin-notifications`, mobile only) with `set-device-info` at every unlock and whenever a mediator is chosen, and removes it on disconnect and sign-out; the mediator's push is a visible notification whose title and text are keys (`almena_wake_title`, `almena_wake_body`) into the app's own strings in `src-tauri/push/`, and nothing runs in the wallet when it arrives. Plain HTTP only for loopback in debug builds. The protocol rules are the mediator's `docs/didcomm.md` §4–5.
- Plugins per platform (`src-tauri/src/lib.rs`): `single-instance`, `window-state` and the system tray on a computer (`tray.rs`: closing the window hides it while the tray is up — live delivery keeps running — the left click and the macOS Dock bring it back, the menu's one entry, named by the front end in its language (`src/tray.ts`), quits; `window.rs` hides and shows the window, emits `window-shown` so the auto-lock is checked on return, and puts a restored window on a screen that exists; the glyphs come from `assets/branding/tray` via `task icons`); `barcode-scanner` on a phone or tablet only, where the Scan QR tab appears (`platform_info` says so, `src/platform.ts`); `deep-link` everywhere, for `almena://` — the scheme the wallet's own invitations are written with. A link or a scanned code is classified by `invitation_kind` (contact, mediator, unknown) and carried to the accept-invitation or connect-mediator screen, prefilled; nothing is acted on until the person confirms, and a link that arrives while locked waits for the unlock (`src/links.ts`, `App.tsx`). macOS only routes `almena://` to an installed bundle; Linux and Windows register it at startup.
- `src/screens/onboarding/` — welcome, phrase, confirmation quiz, restore; then `PinSetup`. `App.tsx` decides between onboarding, the lock (`PinScreen`) and the tabs from `vault_status`.
- `src/screens/MessagesTab.tsx` — the inbox (`MessagesScreen`), a conversation (`ConversationScreen`) and its contact (`ContactScreen`, the alias), and what the "+" leads to: `NewConversationScreen` (directory search — not published yet — above the contacts). `InviteScreen` (QR from `src/qr.ts`, a dependency-free ISO 18004 encoder) and `AcceptInvitationScreen` are still routed in `MessagesTab` but nothing links to them since the invite card was removed. The third tab is Profile (`src/screens/ProfileScreen.tsx`): at the top the identity's picture and its name, shown only (`ProfileHeader`, over `Avatar`); the picture is shrunk to a 512-pixel JPEG in the interface (`src/photo.ts`) and sealed on the device by `messaging/photo.rs`, never sent. Under it a menu of sections in `src/screens/settings/`, each a screen of its own, the shape of the previous Almena ID wallet's settings: Profile (where the picture and the name are changed: `PhotoEditor`, `ProfileCard`), Appearance (identity colour and light/dark), Messaging (the mediator, `MediatorCard`) and Security (change the PIN — `PinChange` —, biometrics — `PinConfirm` —, auto-lock after 1, 5 or 10 minutes of no use, where the record is kept, sign out). Auto-lock (`src/autolock.ts`, `src/lock.ts`) drops the identity from memory rather than hiding it; the clock counts across time spent in the background and is checked when the wallet is seen again. A section is listed only once there is something in it. Messages arrive live while the wallet is visible (`src/live.ts` follows `visibilitychange`); screens also sync on opening and from their sync button. In the background the mediator notifies instead (`src/push.ts`).
- `src-tauri/gen/android`, `src-tauri/gen/apple` — native projects from `tauri android|ios init`; regenerated, so settings that must survive live in `src-tauri/Info.ios.plist`, `src-tauri/push/` (applied by `push/sync.sh`, which the init tasks run; it patches the Xcode project instead of running xcodegen, whose output differs from Tauri's) and the Taskfile. `google-services.json` is the publisher's and is not committed.
- `assets/branding/` — source artwork; `task icons` regenerates `src-tauri/icons` and `public/brand`. Android launcher icons under `src-tauri/icons/android` are hand-drawn.
- `src/styles/global.css` — the only place a colour is written; palettes keyed by `data-theme` and `data-accent` on the root.

The look follows the previous Almena ID wallet (github.com/almena-id/wallet, branch `develop`).

## Rules

- Everything is written in English.
- User-facing text is translatable: English (`en`) is the source language, Spanish (`es`) the first translation. No hard-coded user-facing strings.
- Tasks live in `Taskfile.yml` (`task --list`). Before finishing a change: `task check` (and `task check:mobile` when Rust changed).
- Against a local mediator: in `../mediator`, `ALMENA_PUBLIC_URL=http://localhost:8080 task dev:memory`; (add `ALMENA_RATE_LIMIT=0` for repeated test runs); then `cargo test -- --ignored` in `src-tauri`, or paste `http://localhost:8080` (or its `/oob?_oob=…` link) in Settings → Mediator. The iOS simulator reaches the host's `localhost`.
